==================================================
PROJECT SOURCE OF TRUTH
==================================================

Этот документ является главным техническим заданием и
источником истины (Source of Truth) для проекта DBMUSIC.

При каждой работе над проектом:

1. Сначала изучи этот документ.
2. Определи, какие требования уже реализованы.
3. Определи, какие требования реализованы частично.
4. Определи, какие требования ещё не реализованы.
5. Не удаляй и не изменяй существующую функциональность,
   если это не требуется архитектурой проекта.
6. Не придумывай новую архитектуру, которая противоречит
   этому документу.
7. Если текущее состояние кода отличается от этого документа,
   сначала проанализируй различие и объясни его.
8. Перед внесением крупных изменений проверь, какие пункты
   проекта могут быть затронуты.
9. После каждого значимого этапа обновляй статус реализации.
10. Никогда не считай задачу выполненной только потому,
    что соответствующий код был написан. Проверяй, что
    функциональность действительно работает.

ПРОМПТ: DBMUSIC — ПОЛНОЦЕННАЯ МУЗЫКАЛЬНАЯ ПЛАТФОРМА

Нужно переработать существующий проект музыкального плеера в полноценное закрытое веб-приложение DBMUSIC — собственную музыкальную платформу для нашей компании/круга музыкантов, по концепции похожую на Яндекс Музыку / Spotify, но только для наших исполнителей и наших треков.

КРИТИЧЕСКИ ВАЖНО

В проекте уже существует рабочая первая версия музыкального сайта с треком:

«ЕБАННУТАЯ» — chamxmile, Vzon

На этой странице уже существуют:
- музыкальный плеер;
- обложка;
- play/pause;
- progress bar;
- время трека;
- текст песни;
- комментарии;
- рейтинг;
- модальное окно;
- специальный «кружок» со story-видео;
- loading GIF;
- логика показа кружка.

Эта страница является первой исторической страницей проекта.

ЕЁ НЕЛЬЗЯ УДАЛЯТЬ И НЕЛЬЗЯ ПОЛНОСТЬЮ ЗАМЕНЯТЬ НОВЫМ ПЛЕЕРОМ.

Она должна остаться внутри новой платформы как:

FIRST PAGE / ARCHIVE / THE BEGINNING

1. НОВАЯ СТРУКТУРА

Создать полноценное SPA-приложение:

DBMUSIC

/
├── Главная
├── Треки
├── Артисты
├── Страница артиста
├── Страница трека
├── FIRST PAGE
├── Вход
└── Панель загрузки

Основные маршруты:

/
/home
/tracks
/artists
/artist/:id
/track/:id
/first
/login
/upload

Если используется GitHub Pages, использовать routing, совместимый с GitHub Pages, например hash-routing.

2. ГЛАВНАЯ СТРАНИЦА

Главная страница больше НЕ должна быть текущим одиночным плеером.

Она должна выглядеть как полноценный музыкальный сервис.

На главной:

DBMUSIC

Новые релизы

[TRACK] [TRACK] [TRACK] [TRACK]

Популярное

[TRACK] [TRACK] [TRACK]

Артисты

[ARTIST] [ARTIST] [ARTIST] [ARTIST]

Карточка трека:
- обложка;
- название;
- исполнители;
- кнопка play;
- возможно, количество прослушиваний.

3. АРТИСТЫ

Создать отдельную таблицу artists.

Например:

chamxmile
Лёша
Илья
Саня

Каждый артист получает собственную страницу:

/artist/chamxmile
/artist/lesha
/artist/ilya
/artist/sanya

На странице:
- аватар;
- имя;
- описание;
- все его треки;
- релизы;
- возможность запустить любой трек.

4. СИСТЕМА АККАУНТОВ МУЗЫКАНТОВ

Это обязательная часть проекта.

Каждый музыкант должен иметь свой аккаунт.

Например:

Лёша
login: lesha
password: ********

Илья
login: ilya
password: ********

Саня
login: sanya
password: ********

Также должен существовать отдельный аккаунт администратора.

Например:

admin

НЕ хранить пароли напрямую в JavaScript, HTML или открытых файлах проекта.

Использовать Supabase Auth для авторизации.

5. РОЛИ ПОЛЬЗОВАТЕЛЕЙ

Создать систему ролей:

admin
artist

У каждого пользователя должен быть профиль, связанный с конкретным артистом.

Например:

user
↓
artist_id
↓
Лёша

Таким образом система понимает:

этот аккаунт принадлежит Лёше.

6. ПАНЕЛЬ МУЗЫКАНТА

После авторизации музыкант попадает не в админку всего сайта, а в свою личную панель.

Например:

DBMUSIC STUDIO

Привет, Лёша

Мои треки

[ЕБАНУТЫЙ ТРЕК]
[НОВЫЙ ТРЕК]

+ Загрузить трек

В панели должны быть:
- мои треки;
- добавить трек;
- редактировать свои треки;
- удалить свои треки;
- посмотреть статус загрузки.

7. ЗАГРУЗКА ТРЕКА

При нажатии:

+ Загрузить трек

открывается форма:

Название трека
[________________]

Исполнитель
[автоматически выбран текущий пользователь]

Обложка
[Загрузить изображение]

Аудиофайл
[Загрузить MP3]

Текст песни
[________________]

[Загрузить трек]

При необходимости добавить:
- альбом;
- жанр;
- год;
- описание.

Но базовая форма должна оставаться простой.

8. ОГРАНИЧЕНИЕ ДОСТУПА

КРИТИЧЕСКИ ВАЖНО:

Лёша должен иметь возможность работать только со своими треками.

Например:

Лёша
↓
track_id 1
track_id 2
track_id 3

Он НЕ должен иметь возможности:
- изменить трек Ильи;
- удалить трек Сани;
- редактировать чужую обложку;
- изменить чужой текст.

Это должно обеспечиваться не только интерфейсом, но и на уровне Supabase Row Level Security (RLS).

То есть даже если пользователь вручную отправит запрос к Supabase, он не должен получить доступ к чужим данным.

9. АДМИНИСТРАТОР

Администратор имеет полный доступ.

Администратор может:
- создавать пользователей;
- создавать артистов;
- связывать пользователя с артистом;
- видеть всех музыкантов;
- видеть все треки;
- редактировать любой трек;
- удалять любой трек;
- менять обложки;
- менять тексты;
- управлять комментариями;
- управлять рейтингами;
- управлять FIRST PAGE.

Создать отдельную страницу:

/admin

10. УНИВЕРСАЛЬНЫЙ ПЛЕЕР

Существующий плеер необходимо переработать в универсальный Player Component.

Сейчас он жёстко привязан к:

ЕБАННУТАЯ
cover.png
track.mp3

Нужно убрать эту жёсткую привязку.

Плеер должен получать:

track.id
track.title
track.audio_url
track.cover_url
track.lyrics
track.artists

из базы данных.

Один компонент должен воспроизводить любые треки.

11. ГЛОБАЛЬНЫЙ MINI PLAYER

Добавить нижний фиксированный плеер.

Пример:

┌──────────────────────────────────────────────────────────┐
│ COVER │ ЕБАННУТАЯ — chamxmile, Vzon    ▶ ─────── 🔊    │
└──────────────────────────────────────────────────────────┘

Он должен сохраняться при переходе:

Главная
↓
Артисты
↓
Артист
↓
Другой трек

Музыка не должна автоматически останавливаться при навигации внутри SPA.

12. FIRST PAGE — ОСОБЫЙ РЕЖИМ

Это один из самых важных пунктов.

Текущая страница:

ЕБАННУТАЯ
chamxmile, Vzon

становится специальной страницей:

/first

Она должна быть помечена:

page_type = "first"

или другим аналогичным флагом.

13. КРУЖОК ДОЛЖЕН ОСТАТЬСЯ ТОЛЬКО НА FIRST PAGE

Критически важно:

функция «кружка» НЕ должна работать на новых треках.

То есть:

/first
↓
старый плеер
↓
кружок
↓
story

Но:

/track/123
↓
новый универсальный плеер
↓
БЕЗ кружка

Для всех новых треков:
- обычное воспроизведение;
- play/pause;
- progress;
- lyrics;
- comments;
- rating.

Никакого автоматического кружка.

Существующая логика story, loading, storyOverlay, storyVideo, таймеров и localStorage должна остаться изолированной от новой системы и работать только внутри FIRST PAGE.

14. СУЩЕСТВУЮЩИЕ КОММЕНТАРИИ НЕ УДАЛЯТЬ

Это критически важно.

На текущей странице уже существуют комментарии к треку:

ЕБАННУТАЯ

Их нельзя потерять при миграции.

Все существующие комментарии должны остаться привязанными именно к:

track_id = FIRST_TRACK_ID

То есть:

FIRST PAGE
    ↓
ЕБАННУТАЯ
    ↓
старые комментарии

После создания новой системы пользователь должен открыть /first и увидеть те же самые существующие комментарии, которые были на старом сайте.

Не создавать новую пустую таблицу комментариев.

Не удалять старые записи.

Не переносить их в другой трек.

Не обнулять счётчик комментариев.

15. РЕЙТИНГ FIRST PAGE

Аналогично сохранить существующие оценки/рейтинг первого трека.

Текущая система рейтинга должна продолжить работать для:

ЕБАННУТАЯ

Новые треки получают собственные рейтинги.

Таким образом:

ЕБАННУТАЯ
 ├── старые комментарии
 ├── старые оценки
 └── старый рейтинг

НОВЫЙ ТРЕК
 ├── свои комментарии
 └── свой рейтинг

16. ТЕКУЩИЙ ВИЗУАЛ FIRST PAGE НЕ ЛОМАТЬ

FIRST PAGE должна максимально сохранить нынешний внешний вид.

Не превращать её в новую карточку.

Не удалять:
- существующую обложку;
- текущий плеер;
- lyrics;
- комментарии;
- rating;
- кружок;
- loading;
- modal;
- существующие анимации.

Это отдельная историческая версия сайта.

Можно добавить небольшую подпись:

FIRST PAGE
THE BEGINNING OF DBMUSIC

Но сам плеер оставить узнаваемым.

17. НОВЫЕ ТРЕКИ

Все новые треки, загруженные музыкантами, автоматически становятся обычными:

page_type = "normal"

И появляются:
- на главной;
- в списке треков;
- на странице соответствующего артиста;
- в поиске.

При открытии нового трека используется уже новый универсальный Player.

18. SUPABASE DATABASE

Использовать существующий Supabase.

Не создавать новую отдельную backend-систему, если существующий Supabase позволяет реализовать задачу.

Предусмотреть структуру примерно:

artists
----------------

name
avatar_url
bio
created_at

profiles
----------------

artist_id

created_at

tracks
----------------
id
title
audio_url
cover_url
lyrics
owner_artist_id
page_type
created_at

track_artists
----------------
track_id
artist_id

comments
----------------
id

author_name
text
rating
created_at

При необходимости отдельная таблица:

ratings
----------------
id
track_id
user_id
rating
created_at

19. SUPABASE STORAGE

Использовать Supabase Storage.

Предусмотреть:

audio/
covers/
avatars/
stories/

Музыкант при загрузке должен иметь возможность загрузить:

MP3
+
обложку
+
текст

После загрузки ссылки сохраняются в tracks.

20. АРХИТЕКТУРА КОДА

Не создавать один огромный script.js.

Разделить проект на модули:

js/
├── app.js
├── router.js
├── supabase.js
├── auth.js
├── player.js
├── tracks.js
├── artists.js
├── comments.js
├── ratings.js
├── lyrics.js
├── upload.js
├── admin.js
├── first-page.js
└── ui.js

Особенно важно отделить:

first-page.js

от:

player.js

чтобы специальная логика старого плеера не попадала в обычные треки.

21. БЕЗОПАСНОСТЬ

НЕ хранить:
- пароли;
- service role key;
- административные секреты

в HTML/JS.

Использовать Supabase Auth.

Использовать RLS для:
- tracks;
- comments;
- ratings;
- profiles;
- artists.

Пользователь должен иметь доступ только к разрешённым данным.

22. СОХРАНИТЬ СУЩЕСТВУЮЩИЕ ДАННЫЕ

Перед изменением базы обязательно определить:
- какие таблицы уже существуют;
- какие поля в них используются;
- какие записи уже находятся в Supabase;
- какие комментарии относятся к текущему треку;
- какие рейтинги уже существуют;
- какие Storage-файлы уже используются.

НЕ удалять существующие данные ради новой структуры.

Если необходимо изменить структуру — сделать миграцию так, чтобы старые данные продолжили работать.

Текущая страница не уничтожается.

Она становится уникальной FIRST PAGE, вместе со своими существующими комментариями, рейтингом и кружком.

А всё новое строится уже вокруг неё как полноценная музыкальная платформа.

Каждый музыкант получает собственный аккаунт и может самостоятельно загружать свои треки через личную панель.

Каждый музыкант может управлять только своими треками.

Администратор может управлять всем проектом.

Новые треки используют новый универсальный плеер без кружка.

Кружок существует только на FIRST PAGE.
